# DSL SPEC v1.0 — Orquestador Universal

Schema declarativo que Claude Code (o cualquier LLM) puede leer y ejecutar.
Define: loops anidados, bucle principal, verificación continua, chat interface, sin escalada prematura.

## Estructura raíz

```yaml
version: "1.0"
meta:
  name: <string>
  description: <string>
  goal_hash: <auto-generated SHA256>
chat_interface:
  input_format: <markdown | json>
  output_format: <markdown | json>
  commands: [<lista de comandos>]
  error_format: <string template>
orchestrator:
  max_loops: <int, default 100>
  stop_on_complete: <bool, default true>
  escalate_after: <int, default 2>
  providers:
    mavis: {model: mavis/minimax-m3, api_key_env: ORCH_API_KEY}
    cerebras: {model: cerebras/<model>, api_key_env: CEREBRAS_API_KEY}
    nvidia: {model: nvidia_nim/<model>, api_key_env: NVIDIA_API_KEY}
loops: [<lista de Loop objects>]
```

## Loop object

```yaml
- id: L1_<nombre>
  type: <execute | verify | validate | repair | judge | plan>
  depends_on: [<ids>]
  gate: <completitud | coherencia | formato | sandbox_isolation | repairs_ok | approval>
  provider: <mavis | cerebras | nvidia>
  model: <string>
  agent: <claude_code | mimo_code | opencode>
  sandbox: <sandbox_id>
  repair_max: <int, default 2>
  timeout_s: <int, default 300>
  inputs: {<key>: <value o ${node_id.field}>}
  outputs: [<field names esperados>]
  verify:
    inside_sandbox: <bool>
    command: <string>
  nested_loops: [<Loops anidados>]
  on_fail:
    action: <retry | repair | escalate | stop>
    target: <node_id>
```

## Tipos de loop

- `plan`: descompone el goal en sub-objetivos
- `execute`: ejecuta el código (Claude Code / Mimo Code / OpenCode)
- `verify`: corre tests dentro del sandbox
- `validate`: corre lint/format/type-check
- `repair`: genera un patch mínimo
- `judge`: 3 simulaciones (real / adversarial / regression)
- `consensus`: 3 modelos en paralelo, elige 2-de-3

## Reglas de no-escalada

- Si `escalate_after > 0`, el orquestador re-intenta hasta N veces antes de escalar.
- `stop_on_complete: true` evita que el orquestador termine prematuramente.
- El bucle principal recorre `loops` en orden topológico hasta que todos estén `ok` o se agote `escalate_after`.
- Cada `repair` cuenta como 1 intento; si llega a `repair_max` y sigue fallando, escala.
- El log de cada intento queda en `workflow_state.json` (P0-1: persistencia atómica).

## Ejecución

```bash
python main_dsl.py --dsl dsl_ejemplo.yaml
```

El runtime:
1. Parsea el YAML
2. Construye el DAG
3. Valida (dependencias existen, providers configurados)
4. Ejecuta loop por loop, esperando verificación
5. Si un loop falla → repara hasta N veces → escala al director (Telegram)
6. NO termina hasta que todos los loops estén en `ok` o se haya escalado
