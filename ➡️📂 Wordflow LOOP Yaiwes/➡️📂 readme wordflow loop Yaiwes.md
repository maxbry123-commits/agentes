# FLUJO BASE DEL WORDFLOW LOOP — REGISTRADO, TODAVÍA NO PROGRAMADO

1. El Director entrega **un segmento** del Wordflow.
2. Se conserva ese segmento como **INPUT literal**.
3. Se extrae **solo el mecanismo que debe existir** en el Wordflow; no se inventan pasos adicionales.
4. El Wordflow se construye **por capas y archivos separados**, nunca como un bloque monolítico.
5. Cada mecanismo aprobado se convierte después en un **módulo Python separado** dentro de su capa correspondiente.
6. Todo módulo es **determinista por defecto**.
7. Solo una capa que necesite **decisión o razonamiento** puede usar LLM.
8. Cada capa que use razonamiento tendrá un **skill pequeño específico**, limitado a esa función.
9. La salida de una LLM no ejecutará directamente cambios: deberá volver al control determinista de contratos/validación antes de cualquier ejecución.
10. Cada archivo de código deberá usar **ficha/contrato + plugin/Enchufe Universal** para conectarse al microkernel y a otros agentes.
11. Las capas se conectarán mediante entradas/salidas y contratos explícitos, no mediante dependencias ocultas.
12. El Director irá indicando qué agentes se conectan y qué segmento corresponde a cada capa.
13. Los **3 procesos adicionales** quedan sin definir hasta que el Director los entregue; no se asumen nombres ni comportamiento.
14. La programación del código comienza únicamente después de autorización explícita `APROBADO` o `INTÉGRALO` para el segmento correspondiente.
