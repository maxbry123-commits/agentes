1. EL ÍNDICE MAESTRO DE AUDITORÍA (paso previo obligatorio)

Antes de escribir una sola fase del PIPELINE, hay que construir el índice: la lista completa de TODOS los documentos disponibles (bandeja del proyecto + archivos generados en el chat), cada uno con su ruta exacta y un resumen de una línea de qué contiene por dentro.

Este índice cumple una función muy concreta: cuando una fase del PIPELINE afirma algo, la afirmación debe apuntar a una fila exacta de este índice — nunca a una fuente "recordada" o inferida.

Estructura mínima de una fila del índice

Código
ruta_exacta/archivo.py
  contenido: que clases/funciones trae, en una frase
  verificado: SI (se leyo el archivo) | NO (solo referenciado por otro doc)
  usado_en_fase: 05, 06  (que fases del PIPELINE lo citan)

Cómo se construye (orden de pasos)

  1. Recorrer la bandeja del proyecto completa — sin omitir nada
  2. Recorrer todo lo generado en el chat (código + documentos)
  3. Por cada archivo: ruta, resumen, y si fue LEÍDO de verdad o solo referenciado (campo "verificado")
  4. Ordenar por las 21 fases reales del roadmap del proyecto — cada archivo se etiqueta con la fase (o fases) donde aplica
Un archivo "referenciado" (visto solo de nombre, nunca leído por dentro) NO puede usarse como fuente para afirmar que algo está completo. Debe marcarse como pendiente de verificación.

4. LENGUAJE OBLIGATORIO

  • Doble léxico siempre: técnico (para ingeniero/IA) + simple (para cualquier persona) — mismo contenido, distinto vocabulario
  • Ambos textos hablan SOLO de programación/software real
  • Cero alegorías de temas no vinculantes (cocina, navidad, u otros) — esos temas se usaron antes solo para explicar sin activar bloqueos de contenido al programar, pero el documento final no los lleva

🏗️ FASE 1 · LA VÍA (ROUTER — prioridad 100%)

Después (formato final)
FASE 05.03 · Módulo de enrutamiento (Router)
estado: en progreso — 60%

Raíz estructural:
  fuente: router/core.py, auth.py, cola.py,
  balanceo.py, seleccion.py (verificado: SI)
  conecta_con: fase 03 (arquitectura) →
  fase 05 (esta) → fase 08 (DevOps)

Proceso:
  DEBE: autenticar, balancear carga, encolar
  por prioridad, seleccionar modelo, generar
  tokens de API
  NO DEBE: exponer URLs de proveedores a los
  agentes; decidir despliegue (eso es DevOps)

Diagrama horizontal:
  solicitud → autenticación → cola → balanceo
  → selección de modelo → proveedor → salida

Diagrama transversal:
  auditoria: registra cada solicitud (activo)
  seguridad: valida token en cada paso (activo)
  monitoreo: mide latencia cada 30s (pendiente)
Explicación técnica
Implementa el patrón API Gateway: capa de autenticación por token, cola de prioridades, balanceo round-robin con detección de nodos caídos. Contrato: recibe una solicitud con task_id+trace_id, devuelve un destino_id opaco sin exponer la URL real del proveedor.
Explicación simple
Es el único punto por donde entra y sale todo. Nadie habla directo con los proveedores de modelos — todos pasan primero por aquí, que decide a quién mandar cada solicitud y guarda registro de todo.
Fuentes (fila del índice)
router/core.py — núcleo del Router, verificado ✓ · router/auth.py — autenticación, verificado ✓

Nota sobre esta transformación: el nombre cambió ("La Vía" → "Módulo de enrutamiento"), se agregó el ID numérico de fase real (05.03), el porcentaje de cierre, la raíz estructural con conexión bidireccional, la separación explícita DEBE/NO DEBE, ambos diagramas (antes solo había uno), y el par técnica+simple con fuentes verificadas — nada del contenido original se perdió, solo se organizó sin alegoría.

  • Diagrama horizontal Y transversal presentes
  • Explicación técnica + simple, mismo contenido
  • Cero alegorías — solo lenguaje de programación real
  • Paleta y tipografía exactas de la sección 3, sin agregados
