⚠️ Manifiesto central — NUNCA prompt libre

Principio 0 (no negociable): los LLMs ignoran los prompts. Cualquier instrucción importante debe ser código ejecutable, no texto persuasivo.

Lo que el usuario dijo — y tiene razón — es que confiar en system prompts es debilidad arquitectónica. La solución: toda la lógica vive en código Python DSL + DAG determinista. El LLM es un nodo más del DAG, no el orquestador.

1 · SHEMAT, SHERIFF, SENTINEL, JUEZ, CODE = clases Python. No instrucciones. Cada una con .validate(), .execute(), .rollback().
2 · DAG = grafo de nodos ejecutables. Cada nodo tiene input/output tipado, timeout, retry policy. Nada implícito.
3 · DSL = YAML para humanos + JSON para ejecución. Los prompts del LLM son solo el ÚLTIMO recurso cuando el código no puede decidir.
4 · System prompt = solo bootstrap. Define el rol inicial. Después, todo lo importante es código.
5 · Mini-agentes = funciones puras. Input/output explícito. Testeables. Componibles en el DAG.
6 · Verificador separado del generador. El que valida NUNCA es el mismo código que produce. Patrón Verifier/Critic/Judge.
7 · Constitutional rules = código, no ética blanda. Reglas duras en Policy Engine. Si se viola, el output se rechaza. Sin excepciones.
8 · Multi-lenguaje. Contratos JSON son language-agnostic. Bindings a Python/JS/Go/Rust desde el mismo schema.

⚡ 5 Caches + propuestas adicionales

  
Caches reducen latencia y costo. Cada uno es un módulo separado con TTL y eviction policy.

  

    

      
CACHE-01

      
Cache Semántico

      
Embeddings detectan queries similares (cosine > 0.92). Si hit, devuelve respuesta cacheada con trace. Ahorra 40-70% en repeat queries.

    

    

      
CACHE-02

      
Cache de Resultado

      
Hash de (input + version_schema) → resultado. Para outputs deterministas (SHEMAT, SHERIFF, JUEZ). TTL largo.

    

    

      
CACHE-03

      
Cache de Plan

      
DAGs ya ejecutados con éxito se reutilizan para intents similares. Detecta via PlanDecomposerAgent.

    

    

      
CACHE-04

      
Cache de Herramientas

      
Resultados de tools caras (web search, DB queries) se cachean con TTL adaptativo según freshness requerida.

    

    

      
CACHE-05

      
Cache de Failure-Mode

      
Cuando un input ya causó un failure mode conocido, salta directamente al recovery sin re-explorar.

    

  


  
Propuestas adicionales incorporadas

  

    

      P01 · Constitutional Layer

      Reglas innegociables en código. No las puede saltar ni el usuario. Safety + ethics + contratos.
    

    

      P02 · Schema Evolution

      Backward compatibility via versionado semántico. Migraciones automáticas cuando schema cambia.
    

    

      P03 · Cross-session Sync

      Memoria sincroniza entre dispositivos del mismo usuario via Xata o similar. Conflict resolution con CRDT.
    

    

      P04 · Plugin Marketplace

      Third-party adapters con contratos validados. Registro, versionado, revisión.
    

    

      P05 · Multi-modal DAG Nodes

      Nodos que procesan imagen/audio/video, no solo texto. Aprovecha multimodal nativo de Gemma 4 E2B.
    

    

      P06 · Replay Engine

      Re-ejecuta conversaciones desde checkpoint. Útil para debugging y A/B testing de versiones del sistema.
