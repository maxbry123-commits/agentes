2 · NIVEL 0 — META-LOOP (cada 10s)

INPUT BLOCK · literal
META-LOOP TEAM (cada 10s):
    1. Heartbeat interno
    2. Poll estado de los grupos activos (asyncio.gather)
    3. Re-priorizar tasks (critical > normal > bg)
    4. Decidir siguiente acción (Supervisor)
    5. Handoff al grupo (LangGraph style)
    6. Chequear signals externos (Director, métricas)
    7. Publicar evento al event bus
    8. Self-healing check
Combina 3 patrones: LangGraph Supervisor + BabyAGI + Temporal.

INPUT BLOCK · literal

6 · MÉTODO MHYTOS — 6 FASES EN PARALELO

INPUT BLOCK — MHYTOS = Multi-phase Hyper-cycle Yielding Total Orchestrated Self-improvement. Las 6 fases corren en PARALELO (serializar pierde 90% del valor), se observan cada 10 pasos vía memoria compartida, se refutan vía Refutation Engine (50 preguntas). 
F1 INVESTIGACIÓN  → nunca info obsoleta · web+arxiv+HF+GitHub → investigation.jsonl
F2 PLANIFICACIÓN  → hallazgos → plan.json (10..100 tasks jerárquicos)
F3 EJECUCIÓN      → pull task · si complejo → dynamic_planner · feedback a F4
                    (aquí dispara el Loop Nivel 3 de cada cápsula)
F4 MEJORAS        → async while user_talking: observa→propone→sandbox→mide 10min→persist/revert
F5 REVISIÓN       → agrega F1-F4 · quality vs gold · gaps → restart o HITL
F6 ESTRATEGIA     → 10 hipótesis · simulación · portfolio → alimenta F2
1 iteración MHYTOS = 6 fases × 3 expertos = 18 candidatos + 50 refutaciones + grafo + playbook ≈ 100 unidades de información vs 1 de un loop simple.

6.1 · Reglas duras de MHYTOS (literal)

INPUT BLOCK · literal
- MHYTOS NO genera código: el coder es la flota (S46). MHYTOS encola.
- MHYTOS NO se modifica a sí mismo a nivel código: solo cambia CONFIGURACIÓN
  del pool de expertos y pesos de fase. El código es estable.
- MHYTOS NO habla con el usuario: el runtime TEAM entrega. Roles distintos.
- Memoria compartida OBLIGATORIA: sin ella son 6 agentes sueltos, no MHYTOS.
